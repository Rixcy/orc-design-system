# Prose

One class for a block of rendered Markdown. `.orc-prose` styles the elements a
renderer produces — headings, paragraphs, lists, task checkboxes, code, tables,
links, blockquotes, images, and rules — entirely from `--orc-*` tokens, so the
same block reads correctly in both themes.

<Specimen />

## Using it

`src/styles/prose.css` is opt-in. Import it, then put the class on whatever
wraps the rendered output:

```js
import "@orc-tools/orc-design-system/tokens.css"; // --orc-* palette and fonts
import "@orc-tools/orc-design-system/prose.css";  // .orc-prose
```

```html
<article class="orc-prose">
  <!-- rendered Markdown -->
</article>
```

## What it does not do

`.orc-prose` sets rhythm and colour, never container chrome: no width, padding,
background, or border. The measure and the frame belong to the surface hosting
the prose — a document page wants a different measure to a sidebar preview, and
baking one in would only be overridden.

A wide table scrolls inside itself, which takes a `display: block` that costs the
native table role in some browsers. If a surface needs those semantics intact,
wrap the table in its own labelled scroll container and override the rule —
CSS alone cannot add the wrapper.

Product-specific treatments stay with the product for the same reason. Severity
pills, ticket tables, callouts, lightboxes, and diff views are not prose; they
are components that happen to appear inside it.
