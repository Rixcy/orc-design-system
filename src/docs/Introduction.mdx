# Orc design system

Framework-neutral foundations and Web Components. No runtime dependencies, no
framework: every component is a plain custom element with a shadow root, styled
entirely from CSS custom properties.

## Install

```bash
npm install @orc/design-system
```

```js
import "@orc/design-system/tokens.css";
import "@orc/design-system/components.css";
import { defineOrcElements } from "@orc/design-system/define";

defineOrcElements();
```

Then use the elements as HTML:

```html
<orc-button variant="primary">Send</orc-button>
<orc-chip variant="green" dot>Passing</orc-chip>
```

## How this Storybook is organised

- **Foundations** — the token layer: colour, typography, space and radius.
  Everything on those pages is read live from the token sources, so it cannot
  drift from what ships.
- **Components** — one page per custom element. Each has a **Docs** page with
  an API table generated from the source JSDoc (attributes, slots, events,
  CSS parts and custom properties) plus interactive stories.

## Working here

- The theme switcher in the toolbar (☀️/🌙) sets `data-theme` on the preview
  root — every story should look right in **System**, **Light**, and **Dark**.
- Accessibility violations fail the story: `a11y: { test: "error" }` is on for
  the whole preview, and stories run in CI through `bun run test-storybook`.
- Component API docs come from `custom-elements.json`, regenerated by
  `bun run analyze` (which the `storybook` and `build-storybook` scripts run
  for you). Document new attributes with JSDoc on the component class, not by
  hand.
